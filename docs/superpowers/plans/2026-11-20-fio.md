# Fio Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Loopback-for-Linux Tauri app: virtual audio devices + app/capture routing, living in the system tray.

**Architecture:** Single Tauri v2 app. Rust backend drives audio through PulseAudio's client API (`pipewire-pulse`) behind an `audio/` engine boundary. A pure `reconcile` module turns (desired state, actual Pulse state) into actions — all decisions unit-testable without audio hardware; only the executor touches Pulse. Svelte frontend over Tauri commands/events.

**Tech Stack:** Rust (cargo 1.100), Tauri v2, `libpulse-binding` 2.x, serde/serde_json, uuid; Svelte + TypeScript frontend.

**Spec:** `docs/superpowers/specs/2026-11-20-fio-design.md`

## Global Constraints

- Linux only; requires PipeWire + `pipewire-pulse` (Pulse socket must exist — tests skip if absent).
- Enforcement model, verbatim from spec: **"Fio enforces, never fights"** — heal on launch, enforce only on NEW streams mid-session, flag drift on external removal, never unload a sink with streams attached.
- Module args quoting: `device.description='Name'` uses single quotes (names may contain spaces).
- Device slug: `fio-<slugified-name>` for sink, `fio-<slugified-name>.monitor` for its monitor source (PipeWire's module-null-sink ignores `source_name`/`source_properties` — verified empirically on 1.6.x; the monitor is always `<sink_name>.monitor`).
- Persisted state at `~/.config/fio/state.json`, `version: 1` field required.
- No Flatpak. No JACK. No live source-output moves. No audio processing.
- Conventional commits; `git init` happens in Task 1.

## Review Focus

Inputs the spec implies but no happy-path test covers, most likely first:

1. **Stream with neither `application.name` nor `media.name`** — must not crash matching and must not match every rule. Pinned in Task 6, step 1.
2. **Two devices whose names slugify identically** ("My Mic" vs "my-mic") — must not produce colliding module names. Pinned in Task 2, step 1.
3. **Route target (physical sink) missing at restore time** — reconcile flags drift, never panics or falls back silently to a wrong sink. Pinned in Task 5, step 1.
4. **Deleting a device whose recorded origin sink no longer exists** — streams fall back to default sink. Pinned in Task 7, step 1.
5. **External `pactl unload-module` of our module mid-session** — produces a drift flag, not an auto-reload. Pinned in Task 5, step 1.

**Interfaces:**
- Consumes: Task 1 model types, Task 3 `ActualState`/`StreamInfo`.
- Produces:
  ```rust
  pub enum Action {
      LoadModule { name: String, argument: String },
      UnloadModule { index: u32 },
      MoveStream { stream_index: u32, sink_name: String },
      SetDefaultSource { name: String },
  }
  pub enum Drift {
      MissingDevice { device_id: Uuid },     // our sink_name absent from ActualState
      MissingTarget { route_id: Uuid },      // route's target sink/source not in ActualState
      MissingLink { route_id: Uuid },        // no module-loopback instance matching the route's args
  }
  pub fn plan_startup(desired: &PersistedState, actual: &ActualState) -> Vec<Action>;
  // adopt-by-name: if a sink named fio-{slug} already exists, do NOT reload; if absent -> LoadModule.
  // then MoveStream for each live sink_input matching a rule whose target resolves, and
  // LoadModule module-loopback for each CaptureDevice/VirtualMonitor-sourced route whose link is absent.
  pub fn plan_new_stream(stream: &StreamInfo, desired: &PersistedState, actual: &ActualState) -> Option<Action>;
  pub fn detect_drift(desired: &PersistedState, actual: &ActualState) -> Vec<Drift>;
  pub fn rule_key(s: &StreamInfo) -> Option<&str>;  // app_name.or(media_name)
  ```
